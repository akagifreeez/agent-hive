# 機能リファレンス(ZCode/Codex 比較機能マップ)

目的: hiveは「基本はZCodeの仕組み」を方針とする。この文書は ZCode と Codex が各問題を
どう解決しているかを項目化し、**hiveの現状と採否**を記録する。生の機能一覧ではなく、
「問題 → 解決 → 採否」で読む。

運用ルール:
- これは**スナップショット**である。調査日 2026-09-26。ZCode列は公式ガイド(zcode-guide)とハーネスの実挙動から作成。Codex列は一般知識によるベストエフォートで、確信度の低い箇所は(?)付き。突き合わせは随時やり直す
- 各項目の「判断」がロードマップの種。判断が変わったら本文を上書き訂正し、末尾の📜更新ログに追記する(削除しない)
- 本docはプロジェクト内docであり、D:\working共通層のドキュメント凍結ルールの対象外(本人指示で作成)

## 2. 権限と安全

| 項目 | ZCode | Codex | hive現状 | 判断 |
|---|---|---|---|---|
| 承認モデル | ツール呼出はユーザー選択のpermission modeに従う。破壊的操作は都度確認 | approval modes(read-only / auto-edit / full-auto 等)の段階制 | perm normal/auto の2モード。bashのdeny/askパターン+UI承認カード | 採用済み。細分化(読取無制限/書込承認)は候補 |
| コマンドゲート | hooks(PreToolUse)で拡張側が監視・ブロック | sandboxとapprovalの組合せで制御 | denyパターン即拒否、askパターンはUI承認待ち | 採用済み |
| 操作前フック | hooks 7種(SessionStart〜Stop)。設定ファイルhooksはenabled必須 | hooks的な拡張点は限定的(?) | beforeTool/afterTool/roundEnd のシェルコマンド | 採用済み(最小構成) |
| サンドボックス | ファイルツールはワークスペース基準。OSサンドボックスは別 | workspace-write+ネットワーク遮断のOSサンドボックスが特徴 | ワーカーのファイルツールはworktree内に制限(safePath)。bashはゲート経由 | 採用済み。OSサンドボックスまでは不要(単体デスクトップ前提) |
| 行動規約 | AGENTS.md(ユーザー/ワークスペースの2スコープ、後読みが上書き) | AGENTS.md 発祥。/initで雛形生成 | memory/ 権威ファイル+PC操作制限8か条を全エージェントに常時注入 | 採用済み(マルチエージェント用に翻訳) |
| 監査台帳 | —(permission modeとhooksで事前制御) | — | 全ツール実行を state/audit.jsonl へ1行JSONで記録(agent/tool/ok/ms/cmd/blocked)。5MBで1世代ローテート | 採用済み(2026-09-27、MassGen手本)。PC操作制限の事後検証に使う |
