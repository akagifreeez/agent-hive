# UI/UX計画(モック版) — 操作感とボタン配置の設計

目的: 見た目(ZCode TUIテーマ)に加えて、「何がどこにあって、何を押すと何が起きるか」を
一目で分かるようにする。この計画はまず**モック**(ダミーデータで動く単一HTML)として
試作し、操作感への合意が取れてから本番UIへ反映する。

## 0. 操作の基本原則

1. **場所を選ぶ → 中身を見る → そこに対して操作する** の3層。どの操作も「いま選んでいる場所」に作用する
2. **エージェントを起こす操作と、起こさない操作を分離**:
   - 起こす: メッセージ送信・タスク投入(自動でワーカーが動き出す)
   - 起こさない: タスクの中止/解放/再開/移動、設定変更、表示切替(トークン消費ゼロ)
3. 破壊的な操作(中止/閉じる)は確認ダイアログを挟む
4. 状態が変わったものは、見えている場所に即反映(未読バッジ・進捗・メンバードット)

## 1. 画面レイアウト(3カラム)

```
┌──────────┬─────────────────────────────┬───────────────┐
│ 左:ナビ   │ 中央:会話                    │ 右:状況パネル  │
│          │                             │               │
│ ▸+新規    │ ┌ヘッダ: 名前/目標/メンバー/操作 │ タブ:         │
│ ─────────│ ├─────────────────────────────┤ │ タスク      │
│ メイン    │ │ 会話ストリーム               │ │ エージェント │
│ #cuda    │ │  (あなた/エージェント/       │ │ ファイル     │
│ #cal     │ │   システム行/承認カード)     │ │ ターミナル   │
│ ─────────│ ├─────────────────────────────┤               │
│ 状態line  │ │ 入力欄 + [+] + 候補ポップアップ│               │
└──────────┴─────────────────────────────┴───────────────┘
```

## 2. 左ナビ(スレッド)

| 要素 | 操作 | 結果 |
|---|---|---|
| ＋ 新しいスレッド | 名前と目標を入力→作成 | タブが増え、その部屋に切替。3ワーカー起動 |
| 部屋(クリック) | 部屋を切替 | ストリーム/メンバー/タスクがその部屋のものに変わる |
| 未読バッジ | — | 見ていない部屋の新着数 |

進捗(完了/全体)は部屋名の下に常時表示。

## 3. 中央: ヘッダと操作

- 部屋名・目標(常時表示)
- **メンバーチップ**: 名前+状態ドット。クリック→右パネルのエージェント詳細(思考ログ)へ
- **部屋レベルの操作(セレクタ/ボタン)**:
  - 思考レベル: low/medium/high を即座に変更(次ラウンドから反映)
  - モデル: ドロップダウンでモデル/フォールバックを変更
  - 権限モード: normal(要承認) / auto(自動許可)
  - 部屋を閉じる(スレッドのみ。確認ダイアログ付き)
- これらはクリックした瞬間に効き、ステータスラインに即反映

## 4. 中央: ストリーム(会話)

- 全発言を左揃えのリスト形式で並べる(Discord流)。バブルの左右振り分けはしない
- あなたの発言: 薄いアクセント背景+左端にアクセントの縦線
- エージェント発言: 名前+マークダウン描画。hoverで薄い背景
- ツール実行・思考: エージェント詳細パネルに集約(ストリームには流れない)
- システムイベント(マージ/解放/タスク完了): 1行のグレイ表示
- 承認要求: ストリーム上部に固定カード(承認/拒否ボタン)

## 5. 中央: 入力欄

- 「/」で始めると**コマンド候補がポップアップ**(絞込・クリック補完)
- [+] ボタンまたはペーストで画像添付(送信でその部屋のメンバー全員に届く)
- プレースホルダと「宛先:」表示で、このメッセージが誰に届くかを常時示す

## 6. 右パネル(4タブ)

| タブ | 内容と操作 |
|---|---|
| タスク | プロジェクト別グループ表示。行の操作: 中止/解放/再開/移動。投入フォーム。完了率 |
| エージェント | メンバーのカード+選択中のエージェントの思考ログ(ライブ追従) |
| ファイル | ワークスペースの一覧+内容表示 |
| ターミナル | ワークスペース直下でコマンド実行(出力は履積) |

## 7. 操作フロー(代表シナリオ)

1. **新しい依頼**: メインで壁打ち → リーダーが計画 → 「スレッドを開く」→ 自動で並行作業 → 進捗はナビとヘッダで把握
2. **様子見**: ナビでスレッド選択 → ストリームで経過 → 気になるエージェントのチップをクリック → 思考ログ
3. **軌道修正**: スレッドの入力欄に直接メッセージ(実行中ならターン境界で割込む)
4. **詰み救済**: タスクが止まっていたら、タスクタブで解放→再開、またはメッセージで Push

## 8. モックでの確認ポイント

- ボタンの位置・大きさ・押したときの反応
- 「/」候補の出方、コマンド応答の見え方(消えないこと)
- 進捗と状態の見え方(部屋切替時の切り替わり)
- エージェント思考ログの読みやすさ

## 9. デザイン言語(2026-09-26改訂: 「AI臭」の排除)

**構造はDiscord、色は黒灰+細部のオレンジ**。実在アプリの操作感に寄せることで初見でも迷わせない。

1. **絵文字は使わない**: スレッドは `# 名前`(チャネル記法)、状態は色付きドットで表現。アイコンセットを導入するまでの間、テキストラベルで統一
2. **字体の棲み分け**: UIはサンセリフ(system-ui/Meiryo)。等幅はコード・タスクID・ログ・ターミナル・ファイル一覧のみ
3. **ステータスは日本語**: 待機/作業中/完了/エラー/停止(内部値は英語のまま、表示層で変換)
4. **案内文を書かない**: 「クリックすると〜」の説明は置かず、hover背景・カーソル・配置で押せることを示す。案内文が必要な機能はアフォーダンス設計の失敗として直す
5. **密度**: 行高を詰め、パディングは最小。文字サイズは11/12/13/15の4段階のみ
6. **色は抑制**: 地は黒灰(ニュートラル、青みを入れない)。アクセントはオレンジ1色のみで、細部(選択縦線・リンク・タスクID・アクティブタブ・ログの「発言」ラベル)にだけ使う。青/紫系の飾り色は使わない。状態色(緑/黄/赤)はドットとステータス文字に限定。選択状態は背景+左端2pxの縦線で示す(全画面をアクセントで塗らない)
7. **ネイティブダイアログ禁止**: prompt/confirm/alert はアプリ内ダイアログ(`<dialog>`/オーバーレイ)とトーストで置換
8. **ログの読み方**: 思考/発言/ツール/結果 は等幅ログ内に短いラベル(色分き)で前置きする。絵文字は使わない
